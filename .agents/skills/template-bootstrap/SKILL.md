# 목적
템플릿 저장소를 특정 프로젝트에 맞게 초기 설정하고, 미확정 값을 질문과 문서 갱신으로 정리한다.

## 시작 전 확인
- `docs/PROJECT_PROFILE.md`의 미확정 항목을 확인했는가
- 실제 서비스 코드를 만들지 않는 단계가 맞는가
- 사용자에게서 최소한의 프로젝트 개요를 받았는가

## 암묵 호출 신호
- 프로젝트 이름, 스택, 저장소 구조, 배포 대상이 아직 정해지지 않았다.
- `{{PLACEHOLDER}}`가 많아서 다른 skill을 쓰기 어렵다.
- 새 프로젝트 시작 순서를 먼저 정해야 한다.

## 수행 단계
1. 프로젝트 목적과 범위를 짧게 요약한다.
2. `PROJECT_PROFILE`과 `QUESTIONNAIRE` 기준으로 미확정 항목을 수집한다.
3. 확정값과 placeholder를 구분한다.
4. 표준 명령 이름과 workflow를 프로젝트 맞춤형으로 좁힌다.
5. 배포/운영에서 추측이 필요한 항목은 `TODO(USER):`로 남긴다.
6. 다음 단계에서 어떤 skill을 이어서 써야 하는지 제안한다.

## 산출물
- 갱신된 프로젝트 프로필
- 미확정 항목 목록
- 권장 명령 세트
- 다음 단계 skill 제안

## 완료 조건
- 프로젝트별로 채워야 할 값이 명확히 분리돼 있다.
- 구현 전에 필요한 질문이 문서에 남아 있다.
- 실제 구현 범위로 넘어가기 위한 준비 상태가 분명하다.

## 금지사항
- 실제 기능 코드를 작성하지 않는다.
- 미정 값을 확정된 값처럼 채우지 않는다.
- 배포 구조를 검증 없이 단정하지 않는다.
- 이미 확정된 내용을 문서에 반영하는 일만 남았을 때 `docs-sync` 대신 쓰지 않는다.

## 사용자에게 다시 물어야 하는 경우
- 프로젝트명과 서비스 범위가 바뀌는 경우
- 배포 대상, 인증, 결제, 민감정보 처리 여부가 불명확한 경우
- 자동화 수준이 팀 정책과 충돌하는 경우
