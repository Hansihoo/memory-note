# Memory Assistant Use Cases 002

## 이번 회차 목표
- `암기 어시스턴트`의 사용자 활용 사례를 정리한다.
- 기능 후보를 MVP, 후속 기능, 결정 필요 항목으로 분리한다.
- 개발에 들어가기 전에 모호한 방향을 질문으로 남긴다.

## 제품 한 줄 정의
- Markdown 단어장을 클라우드에 저장하고, key/value 반복 암기와 진행 상태 추적으로 사용자의 복습 루틴을 돕는 학습 도구다.

## 사용자 활용 예시

### 예시 1. 영어 단어를 매일 10분씩 외우는 사용자
- 사용자: 토익이나 수능 영어 단어를 외우는 학습자
- 상황: 이미 Markdown 파일로 정리한 영어 단어장이 있고, 매일 조금씩 반복해서 외우고 싶다.
- 행동:
  - 사용자는 `toeic-vocab.md` 파일을 업로드한다.
  - 앱은 `abandon -> 버리다`, `maintain -> 유지하다` 같은 key/value 항목을 단어장으로 변환한다.
  - 사용자는 출근 전 10분 동안 `오늘 복습`을 시작한다.
  - 모르는 단어는 `잘 모르겠음`, 아는 단어는 `알고 있음`으로 빠르게 넘긴다.
  - 세션이 끝나면 오늘 32개 학습, 8개 다시 보기, 누적 학습일 12일을 확인한다.
- 제품이 제공해야 할 것: Markdown import, 짧은 암기 세션, 잘 모르겠음 기록, 누적 학습일 표시
- MVP 포함 여부: 포함

### 예시 2. 자격증 시험 개념을 질문/답으로 암기하는 사용자
- 사용자: 정보처리기사, 공인중개사, 한국사 등 시험을 준비하는 사람
- 상황: 단어보다 `질문 -> 답` 형태의 개념 암기가 필요하다.
- 행동:
  - 사용자는 `정규화의 목적은? -> 데이터 중복 최소화와 무결성 향상` 같은 항목을 직접 입력한다.
  - 사용자는 잘 모르는 항목을 `잘 모르겠음`으로 표시한다.
  - 앱은 후속 단계에서 반복해서 틀린 항목을 먼저 보여줄 수 있다.
  - 사용자는 정답을 떠올린 뒤 `정답 확인`을 누르고, 스스로 맞혔는지 판단한다.
- 제품이 제공해야 할 것: 범용 key/value 카드, 정답 숨김/확인, 후속 복습 필터
- MVP 포함 여부: 핵심 조작은 포함, 우선순위/상태 필터는 후속

### 예시 3. 개발 명령어와 옵션을 외우는 사용자
- 사용자: 개발자 또는 데이터 분석가
- 상황: 자주 쓰지만 헷갈리는 CLI 명령, Git 명령, SQL 문법을 암기하고 싶다.
- 행동:
  - 사용자는 `git commit --amend -> 마지막 커밋 수정`, `SELECT DISTINCT -> 중복 제거 조회` 같은 항목을 만든다.
  - `key -> value` 방향으로 명령의 의미를 맞히다가, 나중에는 `value -> key` 방향으로 명령 자체를 떠올린다.
  - 자주 틀리는 항목은 `잘 모르겠음` 기록으로 남는다.
  - 사용자는 단어장을 Markdown으로 export해 개인 노트 저장소에도 보관한다.
- 제품이 제공해야 할 것: 양방향 학습, export, 상태 자동 갱신
- MVP 포함 여부: 포함

### 예시 4. 면접 답변을 짧게 반복 연습하는 사용자
- 사용자: 취업 또는 이직 면접을 준비하는 사람
- 상황: 예상 질문과 핵심 답변 키워드를 외우고 싶다.
- 행동:
  - 사용자는 `본인의 강점은? -> 문제를 구조화하고 끝까지 실행하는 점` 같은 카드를 만든다.
  - 답을 완전히 외우기보다 핵심 키워드를 떠올리는 방식으로 학습한다.
  - 사용자는 `잘 모르겠음`을 누른 항목만 모아 다시 연습한다.
  - 나중에는 음성 인식 기능으로 실제 말하기 연습까지 확장할 수 있다.
- 제품이 제공해야 할 것: 긴 value 지원, 잘 모르겠음 모아보기, 후속 음성 인식 확장 여지
- MVP 포함 여부: 기본 학습은 포함, 음성 인식은 후속

### 예시 5. AI로 초안 단어장을 만들고 직접 검수하는 사용자
- 사용자: 새 주제를 빠르게 공부하려는 자기주도 학습자
- 상황: `React Hooks`, `일본 여행 회화`, `회계 기초 용어`처럼 주제는 있지만 단어장 초안이 없다.
- 행동:
  - 사용자는 주제를 입력하고 AI 추천을 요청한다.
  - AI는 key/value 후보 30개를 제안한다.
  - 사용자는 틀린 항목을 삭제하고, 필요한 항목만 단어장에 추가한다.
  - 추가된 항목은 `대기` 상태로 저장된다.
- 제품이 제공해야 할 것: AI 추천, 추천 검수 화면, 중복 제거, 비용/사용량 제한
- MVP 포함 여부: 후속 권장

### 예시 6. 여러 기기에서 같은 단어장을 이어서 쓰는 사용자
- 사용자: 집에서는 PC, 밖에서는 노트북이나 모바일로 공부하는 사람
- 상황: 학습 기록이 기기마다 따로 남으면 복습 상태가 꼬인다.
- 행동:
  - 사용자는 웹에서 단어장을 만들고 학습한다.
  - 다른 기기에서 로그인하면 같은 단어장과 최근 학습 상태가 보인다.
  - 오프라인 상태에서 수정한 항목이 있으면 온라인 복귀 후 동기화한다.
  - 같은 단어가 두 기기에서 동시에 수정된 경우 앱이 충돌을 알려준다.
- 제품이 제공해야 할 것: 로그인, 클라우드 저장, 동기화, 충돌 처리
- MVP 포함 여부: 기본 클라우드 저장은 포함, 복잡한 오프라인 충돌 처리는 후속

### 예시 7. 단어장을 백업하고 다른 도구로 옮기는 사용자
- 사용자: 데이터를 특정 서비스에만 묶어두고 싶지 않은 사용자
- 상황: 서비스가 없어져도 단어장을 개인 파일로 보관하고 싶다.
- 행동:
  - 사용자는 단어장 상세에서 Markdown export를 실행한다.
  - export 파일에는 key/value와 최근 조회한 날짜가 포함된다.
  - 사용자는 파일을 Obsidian, Git 저장소, 클라우드 드라이브에 보관한다.
  - 나중에 다시 import해 같은 상태로 학습을 이어간다.
- 제품이 제공해야 할 것: 안정적인 export/import 포맷, 메타데이터 보존
- MVP 포함 여부: 포함

## 대표 사용자 활용 사례

### 1. Markdown 단어장을 가져와 바로 학습하기
- 사용자는 기존에 가지고 있던 Markdown 단어장을 업로드한다.
- 서비스는 key/value와 최근 조회한 날짜를 읽어 단어장으로 변환한다.
- 사용자는 파싱 결과를 확인하고 잘못 읽힌 행을 수정한 뒤 저장한다.
- 저장 후 바로 암기 세션을 시작한다.

### 2. 새 단어장을 직접 만들기
- 사용자는 단어장 이름을 입력하고 새 단어장을 만든다.
- key와 value를 입력해 단어를 추가한다.
- 필요 없는 단어는 삭제하고, 최근 조회한 날짜는 앱이 학습 흐름에서 자동 갱신한다.
- 단어장이 저장되면 새로 추가된 항목부터 학습할 수 있다.

### 3. 암기 세션 진행하기
- 사용자는 학습할 단어장을 선택한다.
- 앱은 key를 보여주고 value를 맞히게 하거나, 반대로 value를 보여주고 key를 맞히게 한다.
- 사용자는 답을 떠올린 뒤 정답을 확인한다.
- `알고 있음`을 누르면 최근 조회한 날짜와 학습 기록이 갱신된다.
- `잘 모르겠음`을 누르면 정답을 확인하고 학습 기록에 남는다.
- 세션이 끝나면 오늘 학습한 수와 잘 모르겠음으로 표시한 수를 확인한다.

### 4. 잘 모르겠음 중심으로 복습하기
- 사용자는 단어장 상세에서 최근에 `잘 모르겠음`으로 표시한 항목을 다시 본다.
- 필터링된 항목만으로 짧은 복습 세션을 시작한다.
- 반복해서 틀린 항목을 더 자주 노출하는 방식은 후속 복습 알고리즘에서 다룬다.

### 5. AI로 단어장 후보를 추천받기
- 사용자는 주제, 시험 범위, 기존 단어장을 입력한다.
- AI는 key/value 후보를 제안한다.
- 사용자는 추천 항목을 검토한 뒤 필요한 항목만 단어장에 추가한다.
- 잘못된 추천을 바로 삭제하거나 수정할 수 있다.

### 6. 진행률과 학습 기록 확인하기
- 사용자는 프로필 또는 대시보드에서 최근 학습한 단어장을 본다.
- 오늘 학습한 단어 수와 잘 모르겠음으로 표시한 단어 수를 확인한다.
- 누적 학습일을 확인한다.
- 최근 학습한 단어장으로 빠르게 돌아간다.

### 7. 다른 기기에서 이어서 학습하기
- 사용자는 웹에서 만든 단어장을 저장한다.
- 나중에 Chrome 확장, Windows 앱, 모바일 앱에서 같은 단어장을 불러온다.
- 각 클라이언트에서 학습한 결과는 클라우드에 반영된다.
- 충돌이 생기면 최신 수정 기준 또는 사용자 선택 기준으로 병합한다.

### 8. 백업과 이관을 위해 export하기
- 사용자는 단어장을 Markdown 파일로 export한다.
- export 파일에는 key/value와 최근 조회한 날짜가 포함된다.
- 사용자는 다른 계정 또는 로컬 파일 관리 도구로 단어장을 옮길 수 있다.

## MVP 후보 범위
- 어학 단어 학습자 중심 웹 앱
- 계정 기반 클라우드 저장
- 단어장 목록, 생성, 수정, 삭제
- 단어 항목 추가, 수정, 삭제
- Markdown import/export
- 암기 세션
- key -> value, value -> key 방향 전환
- `알고 있음`, `잘 모르겠음`, `정답 확인` 조작
- 최근 조회한 날짜와 학습 기록 자동 갱신
- 단어장별 진행 상태와 누적 학습일 요약

## 후속 기능 후보
- AI 추천
- 음성 인식 답변
- Chrome 확장 프로그램
- Windows 앱
- 모바일 앱
- 오프라인 학습과 지연 동기화
- 고급 spaced repetition 알고리즘
- 공유 단어장 또는 공개 단어장 마켓

## 사용자 스토리 초안
- As a learner, I want to import a Markdown wordbook so that I can start studying from my existing notes.
- As a learner, I want to create and edit key/value entries so that I can build a personal memorization list.
- As a learner, I want to study in both key-to-value and value-to-key directions so that I can recall both sides of the pair.
- As a learner, I want to mark an item as known or unknown quickly so that the study session does not slow down.
- As a learner, I want wrong and high-priority items to come back more often so that weak items get more practice.
- As a learner, I want to export my wordbook as Markdown so that I can back up or move my data.
- As a learner, I want to see progress by wordbook so that I know what is still in progress.

## Acceptance Criteria 초안
- [ ] 사용자는 새 단어장을 만들고 이름을 수정할 수 있다.
- [ ] 사용자는 key/value 단어를 추가, 수정, 삭제할 수 있다.
- [ ] 사용자는 Markdown 파일을 업로드해 단어장을 생성할 수 있다.
- [ ] Markdown import 실패 시 어느 행이 실패했는지 확인할 수 있다.
- [ ] 사용자는 단어장을 Markdown 파일로 export할 수 있다.
- [ ] 암기 세션은 key -> value와 value -> key 방향을 모두 지원한다.
- [ ] `정답 확인` 전에는 답이 숨겨져 있고, 확인 후 `알고 있음` 또는 `잘 모르겠음`을 선택할 수 있다.
- [ ] 학습 결과는 최근 조회한 날짜와 누적 학습일 계산에 반영된다.
- [ ] 프로필 또는 대시보드는 단어장별 진행 상태와 누적 학습일을 보여준다.

## 실패와 예외 흐름
- Markdown 파일 형식이 맞지 않아 일부 행을 읽을 수 없다.
- 같은 단어장 안에 중복 key가 있다.
- key 또는 value가 비어 있다.
- 네트워크 오류로 저장 또는 동기화가 실패한다.
- 두 기기에서 같은 단어를 동시에 수정한다.
- AI가 중복되거나 부정확한 추천을 만든다.
- 너무 큰 단어장을 업로드해 화면이 느려진다.
- 사용자가 실수로 단어장을 삭제한다.

## 개발에 문제가 되거나 방향이 모호한 부분
- Markdown 표준 포맷: 앱과 LLM이 안정적으로 읽기 쉬운 YAML frontmatter + fenced JSON 데이터 블록을 우선 후보로 둔다.
- `단어장`의 범위: MVP는 어학 단어 학습자 중심이지만 key/value 구조는 범용 확장 가능하게 둔다.
- 인증 정책: 클라우드 동기화를 하려면 로그인 또는 사용자 식별이 필요하다.
- 동기화 정책: 웹, 확장, Windows 앱을 모두 고려하면 version, deletedAt, conflict 정책이 필요하다.
- 진행 상태: MVP 필수 필드는 `key`, `value`, `최근 조회한 날짜`이며, `알고 있음`/`잘 모르겠음` 기록을 별도 학습 이벤트로 저장할지 정해야 한다.
- 학습 기록 일수: 프로필 지표는 누적 학습일로 확정됐다.
- AI 추천: 후속 기능으로 둔다.
- 다중 플랫폼: 처음부터 앱/확장/Windows까지 만들면 MVP가 커진다. 웹 MVP 후 확장이 권장된다.

## 권장 첫 개발 범위
- 웹 앱 MVP를 먼저 만든다.
- AI, 음성 인식, Chrome 확장, Windows 앱은 후속 단계로 둔다.
- Markdown import/export와 암기 세션을 1차 핵심 기능으로 둔다.
- 최근 조회한 날짜와 학습 이벤트 기반으로 먼저 만들고, spaced repetition은 데이터가 쌓인 뒤 확장한다.
