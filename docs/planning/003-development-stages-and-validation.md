# Development Stages 003

## 최종 기능 리스트

### 1. 단어장
- 단어장 생성
- 단어장 이름 수정
- 단어장 삭제
- 단어장 목록 조회
- 단어장 상세 조회
- 단어장 클라우드 저장

### 2. 단어
- 단어 추가
- 단어 수정
- 단어 삭제
- 단어 목록 조회
- 엑셀형 표에서 단어 추가와 삭제를 함께 처리
- 새 단어 입력 기본 행은 1줄만 표시
- 화면 아래까지 빈 격자 행 표시
- 질문/답변 열만 셀 선택 표시
- 단어 필수 정보 저장: `key`, `value`, `lastViewedAt`

### 3. Markdown import/export
- 앱이 읽기 쉬운 Markdown 단어장 스펙 정의
- Markdown 파일 업로드
- 업로드한 단어장 미리보기
- import 오류 표시
- Markdown 파일 export

### 4. 암기
- 단어장 선택 후 암기 시작
- 단어마다 `key -> value`, `value -> key` 방향을 랜덤으로 섞어 출제
- 사용자가 제공한 나무 책상 배경 이미지와 HTML/CSS 기반 흰색 줄노트 형태의 암기장 화면
- 암기 시작 버튼 없이 자동으로 첫 문제 표시
- 위쪽 문제 표시
- 아래쪽 답변은 버튼을 누른 뒤 표시
- `알고 있음`
- `모르겠음`
- `알고 있음` 선택 시 답 표시 후 `다음` 버튼으로 다음 문제 이동
- `모르겠음` 선택 시 답 표시 후 `다음` 버튼을 눌러야 이동
- 다음 문제 이동
- 단어별 `lastViewedAt` 갱신

### 5. 프로필
- 누적 학습일 표시
- 오늘 학습한 단어 수 표시
- 단어장별 최근 학습일 표시
- 최근 학습한 단어장 바로가기

### 6. 계정/동기화
- 사용자 로그인
- 사용자별 단어장 분리
- 웹에서 저장한 단어장을 클라우드에 저장
- 이후 앱 클라이언트가 같은 데이터를 읽을 수 있는 API 구조

### 7. 디버깅/검증
- unit test
- integration test
- e2e test
- 디버그 로그 플래그
- production 기본 로그 OFF 또는 warn 이상

## 모든 단계 공통 개발 방식

각 개발 단계는 coding agent가 아래 순서로 반복한다.

1. 이번 단계 목표 확인
2. 구현 범위 확인
3. 테스트 먼저 정의
4. 필요한 디버그 로그 위치 정의
5. 구현
6. unit/integration/e2e 중 해당 테스트 실행
7. 실패 시 디버그 로그를 켜고 원인 확인
8. 수정
9. 같은 테스트 재실행
10. 통과 후 디버그 로그 기본 OFF 확인
11. 결과물과 실패/수정 내역 기록

## 모든 단계 공통 결과물

- 구현된 기능
- 관련 테스트
- 실행한 검증 명령
- 실패한 테스트와 수정 내역
- 디버그 로그 플래그
- production 기본 로그 설정

## 테스트/로그 기본 원칙

- 테스트와 디버그 구조는 1단계부터 같이 만든다.
- 테스트 없는 기능 구현은 완료로 보지 않는다.
- 디버그 로그는 기본 OFF다.
- 문제가 생긴 영역만 플래그로 켠다.
- production에서는 상세 로그를 끈다.
- 단어 내용, 답변 내용, 사용자 토큰은 로그에 남기지 않는다.

## 개발 단계

### 1단계. 웹 기본틀 구현
- 목표: 브라우저에서 단어장을 만들고 단어를 넣고 지울 수 있게 한다.
- 개발:
  - React + Vite 앱 생성
  - 테스트 실행 구조 생성
  - 디버그 로그 플래그 구조 생성
  - 기본 화면 레이아웃
  - 단어장 스펙 정의
  - 임시 로컬 상태 기반 단어장 목록
  - 단어장 생성/삭제
  - 단어 추가/삭제
  - 엑셀형 단어 편집표
  - 단어 목록 표시
- 결과물:
  - 단어장 목록 화면
  - 단어장 상세 화면
  - 단어 추가/삭제 통합 시트
  - unit/e2e 테스트 기본 구조
  - 디버그 로그 기본 구조
- 검증:
  - unit test: 단어 추가/삭제
  - e2e test: 단어장 생성 -> 단어 추가 -> 단어 삭제
  - production 기본 로그 OFF 확인

### 2단계. Markdown 스펙과 import/export 구현
- 목표: 단어장을 파일로 넣고 뺄 수 있게 한다.
- 개발:
  - Markdown 단어장 포맷 확정
  - Markdown parser 구현
  - Markdown serializer 구현
  - 파일 업로드
  - import 미리보기
  - import 오류 표시
  - export 다운로드
- 결과물:
  - Markdown 샘플 파일
  - import 화면
  - export 기능
- 검증:
  - unit test: parser
  - unit test: serializer
  - round-trip test: import -> export 후 데이터 유지
  - e2e test: Markdown 업로드 -> 단어장 생성
- 로그:
  - `DEBUG_IMPORT=true`일 때만 import/export 상세 로그 출력

### 3단계. 백엔드와 DB 저장 구현
- 목표: 단어장과 단어를 서버에 저장한다.
- 개발:
  - FastAPI 앱 생성
  - PostgreSQL 연결
  - 단어장 테이블
  - 단어 테이블
  - 단어장 CRUD API
  - 단어 CRUD API
  - 프런트 API 연동
- 결과물:
  - 백엔드 API
  - DB migration
  - 프런트 저장/조회 연동
- 검증:
  - integration test: 단어장 CRUD API
  - integration test: 단어 CRUD API
  - e2e test: 웹에서 생성한 단어장이 새로고침 후 유지됨
- 로그:
  - `LOG_LEVEL=debug`일 때만 API 상세 로그 출력
  - production 기본값은 `warn`

### 4단계. 로그인과 클라우드 동기화 구현
- 목표: 사용자별로 단어장을 분리해 클라우드에 저장한다.
- 개발:
  - 로그인 방식 결정 후 구현
  - 사용자 테이블 또는 외부 auth 연동
  - 사용자별 단어장 권한 처리
  - 로그인한 사용자 단어장만 조회
  - 로그아웃
- 결과물:
  - 로그인 화면
  - 사용자별 단어장 저장
  - 인증된 API
- 검증:
  - integration test: 로그인하지 않은 요청 차단
  - integration test: 다른 사용자 단어장 접근 차단
  - e2e test: 로그인 -> 단어장 생성 -> 로그아웃 -> 재로그인 -> 데이터 유지
- 로그:
  - `DEBUG_AUTH=true`일 때만 인증 흐름 상세 로그 출력
  - 토큰과 비밀번호는 로그에 남기지 않음

### 5단계. 암기 기능 구현
- 목표: 단어장을 선택해 실제 암기 세션을 진행한다.
- 개발:
  - 암기 시작 버튼
  - 문제 카드 화면
  - 단어별 랜덤 출제 방향
  - 사용자가 제공한 나무 책상 배경 이미지와 흰색 줄노트형 암기 화면
  - 자동 세션 시작
  - 위쪽 문제/아래쪽 숨김 답변 배치
  - `알고 있음`
  - `모르겠음`
  - 다음 문제 이동
  - `lastViewedAt` 갱신
- 결과물:
  - 암기 세션 화면
  - 세션 진행 상태
  - 학습 결과 저장
- 검증:
  - unit test: 세션 상태 전환
  - integration test: `lastViewedAt` 저장
  - e2e test: 단어 3개 암기 후 결과 저장
- 로그:
  - `DEBUG_SESSION=true`일 때만 세션 상태 로그 출력
  - 단어 내용과 답변 내용은 로그에 남기지 않음

### 6단계. 프로필 구현
- 목표: 사용자가 학습 기록을 확인한다.
- 개발:
  - 학습 이벤트 저장
  - 누적 학습일 계산
  - 오늘 학습한 단어 수 계산
  - 단어장별 최근 학습일 표시
  - 최근 학습한 단어장 바로가기
- 결과물:
  - 프로필 화면
  - 학습 요약 API
- 검증:
  - unit test: 누적 학습일 계산
  - integration test: 학습 요약 API
  - e2e test: 암기 후 프로필 수치 변경
- 로그:
  - `DEBUG_PROGRESS=true`일 때만 학습일 계산 로그 출력

### 7단계. 출시 전 정리
- 목표: 실제 사용 가능한 MVP 상태로 정리한다.
- 개발:
  - 빈 상태 화면
  - 로딩 상태
  - 에러 상태
  - 삭제 확인
  - import 실패 메시지
  - 기본 반응형 화면
  - 핵심 e2e 시나리오 고정
- 결과물:
  - MVP 웹 앱
  - 릴리즈 체크리스트
  - 핵심 테스트 시나리오
- 검증:
  - e2e test: 로그인 -> import -> 암기 -> 프로필 확인 -> export
  - build 통과
  - production 로그 기본값 확인
