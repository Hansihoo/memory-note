# DEVELOPMENT_CHECKLIST

## 목적
개발 회차를 시작하기 전에 방향을 잃지 않도록 확인하는 체크리스트다.

## 개발 시작 전
- [ ] 참조할 기능 명세가 있다.
- [ ] 개발 전달 문서가 있다.
- [ ] 이번 회차 목표가 한 문장으로 설명된다.
- [ ] 이번 회차 비범위가 적혀 있다.
- [ ] 필요한 환경값 중 미정 항목이 없다.
- [ ] 이번 회차에서 확인할 테스트 종류가 정해져 있다.
- [ ] 디버그 로그를 켜야 하는 조건과 끄는 조건이 정해져 있다.

## 구현 중
- [ ] 이번 회차 범위를 넘지 않았다.
- [ ] 변경 파일/영역을 알고 있다.
- [ ] 로그를 어디서 볼지 알고 있다.
- [ ] 일반 `console.log` 또는 무조건 실행되는 상세 로그를 추가하지 않았다.
- [ ] 디버그 로그는 기능별 플래그 또는 log level guard 안에 있다.
- [ ] 민감정보, 단어 내용, 답변 내용이 로그에 남지 않는다.

## 구현 후
- [ ] 관련 build 실행
- [ ] 관련 test 실행
- [ ] 관련 lint/typecheck 실행
- [ ] 로그 또는 실제 동작 확인
- [ ] UI 변경 시 Playwright 또는 브라우저 확인
- [ ] 실패 시 디버그 플래그로 원인 위치를 좁혔다.
- [ ] 수정 후 같은 검증 명령을 다시 실행했다.
- [ ] production 기본값에서 디버그 로그가 꺼져 있는지 확인했다.
- [ ] 실패한 것이 있으면 이유 기록

## 권장 테스트 도구
- [ ] 프런트 unit/component: `Vitest` + `React Testing Library`
- [ ] 프런트 e2e: `Playwright`
- [ ] 프런트 타입 검사: `tsc`
- [ ] 백엔드 unit/integration: `pytest`
- [ ] 백엔드 타입 검사: `mypy`
- [ ] 백엔드 lint/format: `ruff`
- [ ] API/DB: integration test와 migration test

## 디버그 로그 체크
- [ ] 기본 `LOG_LEVEL`은 production에서 `warn` 이상이다.
- [ ] import/session/progress/sync 로그는 기능별 플래그로만 켜진다.
- [ ] request id로 프런트와 백엔드 흐름을 연결할 수 있다.
- [ ] 로그 때문에 반복문, 렌더링, 파서가 느려지지 않도록 guard가 있다.

## 문서화
- [ ] 이번 회차에서 결정된 것 기록
- [ ] 보류된 것 기록
- [ ] 다음 회차 시작점 기록

## 완료 판단
- [ ] 기획 의도와 구현 방향이 어긋나지 않는다.
- [ ] acceptance criteria와 연결해 설명할 수 있다.
- [ ] 테스트 실패 또는 로그 확인 결과를 보고 문제 위치를 설명할 수 있다.
- [ ] 다음 회차를 바로 시작할 수 있다.
